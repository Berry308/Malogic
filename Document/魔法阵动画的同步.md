# 最终方案
## 需求分析
需求：

在接收到同步 Actor 时，ViewActor 的构建进度应该要慢于同步 Actor，以便实现动画的追赶而不是回退。

分析：

 ViewActor 获取到的 ClientActualBuildingTime 是客户端根据当前属性（武器，buff）计算出的结果。

而服务器的同步 Actor 的 ServerActualBuildingTime 是减去了一次客户端到服务器的传输延迟（最大 100ms）的 MagicCircleInstance 的实际构建时间。

所以同步 Actor 的构建时间本来就比 ViewActor 少一次传输延迟（最大 100ms）

Actor 的同步信息还要经过一次网络延迟（假设 100ms），那么实际上客户端接收到服务器同步信息时，ViewActor 最多经过了 200ms。由于同步 Actor 减去了一次传输延迟，所以 ViewActor 的构建时间理论上只需要比 ClientActualBuildingTime+单次传输时间(100ms) 长即可。设置成 150ms 以覆盖更广泛的情况。

## ViewActor
职责：

播放动画需要比真正的魔法阵 Actor 构建时间长

通过 WeaponStateComponent->AddUnconfirmedPredictiveViewActor 函数，

 ViewActor 的ActualBuildingTime=魔法阵的 ClientActualBuildingTime + 预留的服务器延迟时间 ServerDelayTime（150ms）

成员：

float ActualBuildingTime

float ServerDelayTime

### 蓝图图表
在 BeginPlay 事件中，根据参数修改材质。

## 同步 Actor
职责：

在服务器实际生成时，通过客户端的 TargetData 计算减去客户端到服务器的传输延迟后的 ActualBuildingTime。

## 流程
+ 客户端调用 MalogicGA_MagicDeploy 技能
+ 计算客户端当前状态的 ActualBuildingTime 并且生成 ViewActor。
+ 在客户端构建 TargetData 时，注入当前服务器世界的权威时间，作为客户端要求生成魔法阵的时刻。
+ 在服务器接收到数据后，生成 MagicCircleInstance 时，会调用 AMalogicMagicCircleInstance::InitializeFromTargetData 函数并传入 TargetData，根据 TargetData 中的时间和当前服务器的时间，计算从该客户端发送，到服务器接收所花费的时间。然后将该魔法阵实例的构建时间减少这个网络传输所花费的时间（<font style="color:#DF2A3F;">最大上限为 100ms，任何魔法阵的构建时间都不应小于 100ms，否则会出现问题</font>）
+ 在客户端预测的 ViewActor 中，其构建时间应该始终大于实际同步 Actor 的构建时间，以便在网络传输延迟过长的情况下，不会导致同步 Actor 动画覆盖而导致的“画面回退”。
+ 动画通过一个成员记录帧时间累加，然后与构建时间相除得出动画播放进度。
+ 在服务器同步到客户端后，设置一个蓝图事件以响应，应该获取 ViewActor 当前播放进度，而同步 Actor 此时应该将 ViewActor 动画播放进度作为起点，经过 ServerActualBuildingTime 才结束构建动画播放。

## 当前已验证实现

+ `MagicCircleViewActor` 由 C++ Tick 累计本地时间，计算并保存 `0~1` 的 `CurrentBuildingProgress`；蓝图通过 `Apply Building Progress` 事件驱动透明度、旋转和其它表现。
+ 客户端为每次预测部署分配 `PredictionId`。服务器将该 ID 保存到 `MagicCircleInstance`，并仅向拥有者复制。
+ 部署成功时确认 RPC 不立即销毁预测 ViewActor；权威 Actor 到达客户端后，通过 `PredictionId` 从 `MagicWeaponStateComponent` 一次性读取预测 Actor 当前进度并销毁它。
+ 权威 Actor 以读取到的预测进度作为起点，在 `ServerActualBuildingTime` 内由客户端本地 Tick 播放到完成，不进行逐帧网络同步。
+ 部署被拒绝时，确认 RPC 立即清理预测 ViewActor。确认 RPC 与权威 Actor 复制可以按任意顺序到达。
+ 若权威 Actor 到达时已经不在 `Building` 状态，则直接应用完成进度，避免残留预测表现。
